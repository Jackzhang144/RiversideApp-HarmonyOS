# 07 — 迁移 Reply 编辑与安全恢复路径

**What to build:** 将 Reply 编辑器迁移到原型确认的原生视觉与反馈基线，同时保持纯文本/Discourse Markdown、草稿保留、401 重新认证和不确定提交确认的安全语义。

**Blocked by:** 05 — 迁移 Topic/Post 阅读完整路径.

**Status:** ready-for-agent

- [ ] 用户可以从 Topic 或指定 Post 打开、收起并继续 Reply，编辑目标和已有草稿保持正确。
- [ ] 编辑器显示实时字符数和“草稿仅保存在本次运行内存中”，不设置原型中未经契约证明的 1000 字限制。
- [ ] 图片和 @提及图标作为视觉降级、无响应的“未实现”占位，不触发上传、导航、插入或业务请求。
- [ ] 空白输入不能提交；提交中和结果确认中正确锁定相关操作并显示清晰状态。
- [ ] 明确拒绝、网络失败、401 和不确定结果均保留草稿；401 重新认证后可以继续编辑。
- [ ] 不确定提交先确认预期 Post，无法确认时只允许用户显式重试，绝不自动再次 POST。
- [ ] 成功与失败使用一致的 HDS SnackBar 反馈，成功后 Topic/Post 状态保持正确。
- [ ] AppShell 自动测试覆盖 Topic Reply、指定 Post Reply、长于 1000 字输入、明确拒绝、401、超时确认、显式重试和避免重复 Reply。
- [ ] 使用 `devecocli` 完成 API 23 构建与 Reply 基础键盘路径验证，且不修改或提交本地签名配置。
