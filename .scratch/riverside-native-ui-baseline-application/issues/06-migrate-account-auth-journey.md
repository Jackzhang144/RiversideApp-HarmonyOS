# 06 — 迁移“我的”与账户认证路径

**What to build:** 将“我的”迁移为始终完整可见的正式账户页面，让用户在不同认证状态下使用真实登录和退出流程、看到明确的未来能力占位，并随时通过悬浮胶囊进入持久原型实验区。

**Blocked by:** 02 — 建立五 Tab HDS 正式根导航.

**Status:** ready-for-agent

- [ ] 未登录、会话恢复、授权错误、已登录和退出中的账户头部与操作状态清晰可见，且不以全屏忙碌状态遮盖整个页面。
- [ ] 已登录头部只显示系统头像、“已登录 RiverSide”和本地会话安全状态，不展示 Fixture 昵称、校友身份、认证徽章或无法证明的资料。
- [ ] 登录和退出登录是本轮唯一真实账户操作，并继续使用现有 Authenticated Session、ArkWeb、HUKS 和全局 401 语义。
- [ ] 个人信息、RSC 钱包、我的 Topic、我的 Reply、我的草稿、我的书签、应用设置和关于 RiverSide 在所有认证状态下均显示为不可点击的“未实现”占位。
- [ ] 每个占位项视觉降级、无导航、无反馈、无业务请求，并通过无障碍文案读出“未实现”。
- [ ] 原型悬浮胶囊在未登录、会话恢复和已登录状态下始终可见，避让根悬浮栏与底部安全区，并能打开和退出原型。
- [ ] 本票不新增个人资料接口，也不新增 Debug/Release 暴露条件。
- [ ] 自动测试覆盖认证状态变化后账户页面所需的外部状态，并证明占位和原型入口不受认证状态影响。
- [ ] 使用 `devecocli` 完成 API 23 构建与账户主路径验证，且不修改或提交本地签名配置。
